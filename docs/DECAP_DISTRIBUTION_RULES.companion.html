핵심 계약

원본 보존

원본 .spd는 덮어쓰지 않는다. Preview는 scenario를 변경하지 않고, Apply는 assignment와 gap을 한 revision에서 원자적으로 검증한다.

물리 증거 우선

목표 수량보다 exact destination copper, 실제 PWR VIA root, shared-pad topology와 source-proven separator가 우선한다.

최대 유효 부분해

목표를 전부 채울 수 없으면 잘못된 후보를 강제하지 않고 최대 유효 결과를 PARTIAL로 반환한다.

Distribution의 FULL/PARTIAL은 수량·topology 결과다. PI Evaluation 가능성과 동일하지 않으며 Apply 후 Original/Tuned를 별도 preflight한다.

계산 파이프라인과 우선순위

Target cell 역할과 destination eligibility

조건역할최종 수량 제약공여/수신 의미
Target < PresentDONORActual ≥ Target여유 범위에서 공여 가능
Target > PresentRECEIVERActual ≤ Target부족분만 수신 요청
Target = Present, tolerance 0UNCHANGEDActual = Present이동·교환 제외
Target = Present, tolerance > 0EXCHANGEActual = Present정해진 turnover 안에서 주고받음
 
Tolerance Count = floor(Present × Tolerance (%) / 100)
Actual = Present - Sent - Sacrificed + Received

Candidate Audit의 Eligible은 destination의 exact copper·VIA root가 유효하다는 뜻이다. 실제 이동에는 source cell이 DONOR 또는 allowance가 있는 EXCHANGE라는 별도 조건도 필요하다.

Local final-copper separator certificate

동일 NET 전체에 Box가 여러 개 있어도, 해당 chain이 놓인 local final component가 정확히 하나의 untouched axis-aligned positive rectangle이면 독립적으로 separator를 인증한다. 로컬 void, re-add, 겹침·edge-tile, boundary-only, non-collinear branch는 인증하지 않는다.

  • 목적 rail 이동
  • source rail 유지
  • isolation gap

최적화 정책의 전체 순서

BALANCED_AUTO / CUSTOM

  1. receiver 충족 수량 최대화
  2. active PWR NET relabel 수 최소화
  3. signed distance + gap penalty × gap 수 최소화
  4. combined objective 동률에서 gap 수 최소화
  5. canonical REFDES/rail 순서

AUTO penalty는 board diagonal, CUSTOM은 사용자가 지정한 유한한 0 이상 값이다.

MIN_GAPS

  1. receiver 충족 수량 최대화
  2. gap 수 최소화
  3. active relabel 수 최소화
  4. NEAREST/FARTHEST distance
  5. canonical 순서

gap 수가 distance보다 항상 먼저인 호환 정책이다.

Candidate Audit를 읽는 법

NO_ZERO_GAP_EXACT_COUNT_COMBINATION은 zero-gap connected atom subset에 대한 설명이다. 인증된 separator로 cluster를 나누는 최종 MILP까지 불가능하다는 판정이 아니다.

결과 수량, Preview와 Apply

  • RECEIVER의 Assignment Failed = max(Target - Actual, 0).
  • DONOR는 Target 아래로 내려갈 수 없으며 이동과 희생 gap 모두 실제 감소다.
  • EXCHANGE는 최종 수량을 유지하고 tolerance count 안에서 sent·sacrificed·received를 제한한다.
  • Preview identity, scenario revision, target, distance mode, optimization policy가 바뀌면 stale이다.
  • Apply는 plan을 재검증하고 assignment와 gap을 함께 commit한다.
주요 fail-closed 진단
  • ISOLATION_GAP_NOT_PROVEN: local source copper가 separator를 인증하지 않음
  • SHARED_PAD_DUMMY_ISLAND: 실제 PWR VIA가 없는 활성 dummy 구간
  • SHARED_PAD_ACTIVE_SHORT: gap 없이 다른 활성 NET이 맞닿음
  • RAIL_INELIGIBLE_AT_PWR_VIA: 구간 root의 목적 rail 증명 실패
  • PLAN_STALE / PLAN_TAMPERED: Preview identity 불일치

v0.22.3에서 반영한 source/UI 변경

PowerNets inventory

decap_scenario는 PowerSI simulation 선택과 무관하게 모든 positive-plane physical PowerNet을 보존한다. selected_pi와 GroundNets 선택 의미는 바꾸지 않는다.

PowerSI Box 좌표

Box는 start-corner X/Y + width/height로 해석한다. 이로써 분리된 pad를 잇는 실제 strip의 bounds와 shared-pad membership을 복원한다.

반응형 Evaluation

PWR NET picker가 form 전체 폭을 사용하고 visible label과 splitter usability를 유지한다.

분리창 직접 편집

Target/Tolerance만 편집 가능하며 메인 표의 canonical validation, preview invalidation, summary를 정확히 한 번 갱신한다.

해석 경계와 원문

이 결과는 배치 계획용 pre-design 증거다. fabricated VIA path, DRC, SI, 제조 가능성 또는 최종 PowerSI/SIwave sign-off를 대체하지 않는다.
