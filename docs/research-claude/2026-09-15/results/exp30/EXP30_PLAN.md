# EXP-30 계획 — held-out 설계 s5m6585(PCB, 160포트) 일반화: R 결손이 패키지 microvia 특유인지 판별

작성 2026-09-17, 실행 전 사전 등록. 소유자 지시(2026-09-17): 실장 기생 옵션은 없다고 가정, PowerDC 경로 R은 후순위. 지금 가능한 판별은 **다른 설계에서 같은 R 결손 패턴이 나오는지**다. s5m6585는 PCB(2층 구조·small-hole void 약 16만 개)로 260729/260804(패키지, microvia 스택)와 급전 구조가 다르다. 기준선: exp28/p(균질화 결함 수정 포함, `c_unit_fix=True, homog_face_fix=True`) — 소유자 명시 승인 전이지만 결함 상태 기준선으로는 held-out 판정이 무의미하므로 p를 쓴다(거부 시 j로 재실행).

## 1. 동결 규칙
- 모델·파라미터·게이트는 260729와 동일. 포트명은 npz `port_names`의 `::` 앞부분. 러너 `run11.py --tag s5m6585 --variant p --outdir exp30`, 드라이버 `runall15.py --tag s5m6585`. 실패 포트는 `failures.json`에 기록하고 코드를 고치지 않는다(원인만 보고).
- 먼저 1포트 시험 실행으로 추출·빌드 시간과 메모리를 확인하고, 포트당 20 min·6 GB를 넘으면 포트 수를 줄여(예: 40포트 무작위, 시드 0) 실행한다 — 이 축소 규칙은 지금 고정한다.

## 2. 가설(동결)
- H_pkg(패키지 특유): s5m6585에서 100 kHz 참조/모델 R 비의 중앙값이 1.15 미만이고 R 결손형(dRe_100k < −0.05 mΩ) 비율이 30 % 미만이면 채택 — 260729의 결손(중앙값 1.46, 결손형 76/92)은 패키지 microvia 스택·핀필드 관례에서 온다. 260729와 같은 수준(중앙값 ≥ 1.3, 결손형 ≥ 60 %)이면 기각 — 설계 무관한 모델 공통 원인.
- H_gate: G3 PASS 비율을 보고만 한다(예측: PCB에서 더 높음).
- 보조: 고립 decap 감사(`audit27.py --tag s5m6585 --variant p`) 0개 확인; 2층·small-hole 처리에서 파서·wall 규칙이 동작하는지(실패 수) 보고.

## 3. 판정 후 해석(미리 적음)
- H_pkg 채택이면 다음 과제는 microvia 스택 R 관례(패드 접속 저항, 스택 via 직렬 R, 코니컬 형상)를 자유 계수 없는 폐형식으로 정식화해 시험한다.
- 기각이면 R 결손은 평면·trace 수준의 공통 원인이며, 평면 R 산정(균질화 이후 남은 차이, 예: 셀 단위 G 정의)을 재검토한다.

## 5. 실행 전 보완 기록 (2026-09-17, 1포트 시험 결과)
- s5m6585 층 이름은 `Plane$IN43_DGND` 형식이라 `Stack.is_gnd`("(DGND)" 포함 검사)가 GND 층을 못 찾아 build가 실패했다. `_DGND` 접미사도 GND로 인식하도록 확장했다(260729/260804 48층 분류 불변, smoke PASS).
- s5m6585의 decap 모델은 `.PartialCkt` 안에 `xcall … / .SUBCKT` 형식(100 nF·100 pF), 이상 소자 한 줄 `C 1 2 1u`(1 µF·220 nF), 빈 본문(NULL)으로 들어 있어 연구 추출기가 전부 `skip_component_no_2port_model`로 버렸다(160포트 decap 0). 이는 형식 차이이지 튜닝이 아니므로, 추출기에 세 형식의 fallback 파서를 추가한다(260729/260804 결과 불변 조건). NULL 부품은 모델 없음으로 제외한다.
- 위 두 보완은 §2 가설·판정에 영향을 주지 않는다.
