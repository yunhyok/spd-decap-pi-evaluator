# EXP-27 계획 — 모델 연결성 감사: 기준면 제외 그래프에서 포트와 끊긴 decap (92포트) + P65 결함 추적

작성 2026-09-17, 실행 전 사전 등록. EXP-26에서 P65_SITE1의 10 µF decap이 모델 안에서 포트와 갈바닉으로 끊겨 있음을 발견했다. 이것이 얼마나 흔하고 R 오차와 얼마나 연결되는지 92포트에서 세고, 결함 기구를 특정한다. 파라미터 변경 없음(감사만).

## 1. 정의(동결)
- 각 포트에서 기준선 모델(exp13/j 규칙, c_unit_fix)을 build한 뒤(풀이 없음), 기준면 노드를 제외한 소자 그래프(평면 엣지·trace·via·패드 링크)의 연결 성분을 구한다. "고립 decap" = 레일 노드가 포트의 성분에 속하지 않는 decap. 포트별로 고립 decap 수, 고립된 C 합/전체 C 합(비율 c_iso), 모델 id 목록을 기록한다.
- 고립 decap의 레일 노드에 대해 extract에서: 노드의 층·좌표, 반경 300 µm 안의 레일 노드·via·trace 끝점, 그 노드가 시트에 스냅됐는지(`rail_nodes_snapped` 판정 재현), 패드스택 이름.

## 2. 가설(동결)
- H_freq: 고립 decap이 1개 이상인 포트가 92 중 ≥ 20 %(≥ 19).
- H_corr: c_iso > 0인 포트의 |dRe_100k|/Re Z_ref 중앙값이 c_iso = 0인 포트보다 크다(Mann–Whitney p < 0.05).
- H_mech(P65 C10105_1): 레일 노드 주변 300 µm 안에 같은 넷의 via 또는 trace 끝점이 있으면 "연결 소자 누락(추출)"; 없고 시트 위에 있는데 스냅이 안 됐으면 "스냅 실패"; 시트 밖에 홀로 있으면 "레이아웃상 고립(부품 내부 연결 등)"으로 분류한다.

## 3. 판정 후 해석(미리 적음)
- H_freq·H_corr 채택이면 연결성 결함이 R 오차의 주요 기구이며, H_mech의 분류에 따라 수정 플래그(추출 보완 또는 스냅 반경)를 사전 등록해 7케이스 + 92포트로 판정한다.
- H_freq 기각(드묾)이면 P65는 개별 사례로 기록하고 급전 경로 R 관례 과제로 돌아간다.

## 4. 산출물
`exp27.json`(포트별 고립 목록·c_iso, P65 추적), `EXP27_REPORT.md`. 코드 `tools/research-claude/exp27/audit27.py`(`--jobs`로 병렬 build, 포트당 캐시). 저장소 사본 `results/exp27/`. 비용: 92 build ≈ 92 × 1–4 min / 7 병렬 ≈ 40 min, 메모리 ≤ 6 GB/포트.
