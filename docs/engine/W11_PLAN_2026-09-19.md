# W11 — `spd_pi_engine`의 제품(`spd_decap_pi`) 통합 계획 (2026-09-19, 사전 등록)

근거: `src/spd_pi_engine/README.md`, `ENGINE_PLAN_2026-09-18.md` §4 W11·§5·W12/W13, `DECISIONS.md` D5/D9, `W5_REPORT.md` §4-3(제품 테스트 기준선), `W13_REPORT.md`, 제품 트리 통독(설계 에이전트, 2026-09-19). 소유자가 D9로 연구 단계를 닫고 "다음 단계"를 지시했으므로 W11을 시작한다. ENGINE_PLAN의 전제("패키지 급전 경로 R 관례 해결 전에는 W11 시작 안 함")는 **게이트가 아니라 validity 문구로 처리**한다 — 엔진 프로파일은 기본값이 되지 않고, 모든 결과에 `VALIDITY_NOTES`가 붙는다. 이 정책은 소유자 확인 사항이다.

## 0. 조사 결과 — 맞아떨어지는 것과 진짜 격차
이미 일치(추가 데이터 불필요): rail 식별자(`RailSpec.rail_id` = SPD net = `ex["rail_net"]`, `_core/services.py:4680-4685`, `_core/io/spd.py:3846-3848`, `spd_pi_engine/multiport.py:68-82`), decap refdes(같은 파서 `_parse_metadata`), 모델 id(같은 `_parse_partial_circuits` canonical), SUBCKT 원문(`attachments["cap_models/{id}-{hash}.lib"]`, `project.metadata["cap_model_sources"]` ↔ `Model.add_decap_model`), SPD 경로/sha256(`ScenarioSpec.source` ↔ `Design.open/sha256`).

진짜 격차 3개: (1) SPD 원본 파일이 있어야 한다(시나리오는 SPD 바이트를 저장하지 않음) → 경로 존재 + sha256 일치일 때만 실행, 불일치는 fail-closed. (2) PWR 재할당(net 이동)은 엔진이 표현 못 함(`ex["decaps"]`는 `.Connect` net 고정) → 레일 밖으로 나간 decap은 `None`, 다른 net에서 들어온 decap이 있으면 해당 레일 평가 거부(preflight 블로커). (3) 주파수 격자: 제품 1 kHz–1 GHz 401점 vs 엔진 사다리 27점(100 MHz 상한) → 엔진 프로파일은 자체 격자(`ladder_freqs()`)를 쓰고 `EvaluationView.frequency_hz`가 그 격자가 된다(`_core/services.py:4485`는 `outcome.solve.frequencies_hz`를 그대로 씀).

## 1. 아키텍처
### 1-1. 프로파일 2개(`_core/solver/profiles.py:82-92` 옆)
`hybrid_plane_pair_v1`(badge HYBRID, reference "powersi-compatible"), `hybrid_plane_pair_v1_gnd`(HYBRID-GND, "physical-gnd"). `experimental=False`(True면 `evaluation.py:3565-3597`의 연구 증거 해시 요구에 걸림). 플래그는 `FLAGS_P` 고정, 노출 안 함. `compiler_algorithm_id`는 정적 식별자, 실제 수치 정체성은 엔진 `numerics_id`.

### 1-2. 어댑터 `_core/solver/engine_adapter.py`
엔진 import는 함수 안에서(역import 순환·기동비용; layerwise도 같은 지연 import, `_core/services.py:841-843`). 공개 함수: `engine_port_for_rail(spd, rail_id)`(`port_rails` 역인덱스, 0개/2개 이상은 에러), `decap_config(scenario, rail_id)`, `extra_models(scenario, attachments, config)`, `solve(EngineSolveRequest) -> EngineSolveResult`(워커 호출 + 영수증 로드). `EngineSolveRequest`(frozen, JSON): spd_path, spd_sha256, port, reference_mode, freqs, cache_dir, solver, configs={role: {refdes: model_id|None}}, extra_models.
- 입력: `Design.open(spd).rail(port, cache_dir).build(ModelOptions(reference=…, flags=FLAGS_P, h=200.0, fh=50.0, top_h=50.0, sub=(20,10,10), fringe=True), Backend(solver, fast=True))` — `tests/engine/test_reproduction.py:29-30`의 `OPT`와 한 글자도 다르면 안 된다.
- 출력: `EvaluationOutcome`(`_core/solver/evaluator.py:278-288`)을 직접 조립해 기존 `_evaluation_view`(`_core/services.py:4477`)로. `solve=ModalSolveResult(freq, Z, SolverDiagnostics)`(`modal.py:616-634`), `metrics=compute_evaluation_metrics(...)`(`metrics.py:139`), confidence는 `assess_confidence` 대신 `ConfidenceAssessment` 3개(<1e5 / 1e5–1e8 / >1e8 LOW "검증 범위 밖"), `assumptions=tuple(receipt["validity"]["notes"])`, `solver_version=f"spd-pi-engine-{engine_version}-{numerics_id[:12]}"`(결과 캐시 키가 엔진 수치 변경 시 자동 분리), `solver_provenance={profile_key, badge, source_only True, powersi_used_for_parameters False, compiler_algorithm_id, static sha, engine_version, numerics_id, receipt_sha256, spd_sha256, decap_config_sha256, prune_basis, unknowns, backend, matplotlib/PIL/numpy/scipy 버전}`.

### 1-3. 삽입 지점 — `evaluation.py`의 40개 layerwise 분기는 건드리지 않는다
진입 함수 3곳 맨 앞에서 갈라낸다: `evaluate_scenario`(`:4564`, `canonical_rail` 확정 `:4581-4592` 직후), `evaluate_comparison_batch`(`:4658`, `resolve_solver_profile` `:4681` 직후), `preflight_evaluation_comparison`(`:2559`, `:2582` 직후). 엔진 preflight 검사 4가지: SPD 경로 존재+sha256, 레일↔SPD 포트 정확히 1개, 교차-net 재할당 없음(블로커 `ENGINE_CROSS_NET_DECAP_ASSIGNMENT`), 메모리 가드는 워커 안에서. Original 구성은 `ScenarioSpec.original_configuration`(`scenario.py:3061`)·`with_baseline_captures`(`:2949`) 재사용. 베이스라인 캐시는 1단계에서 끔(`:3147-3148`, `:3204-3205`에 `or profile in ENGINE_PROFILES`). `_evaluation_settings`(`:516`)에 엔진 분기 6줄(`solver_static_identity_sha256`, `engine={numerics_id, engine_version, reference_mode, freq_grid_sha256, decap_config_sha256}`).

### 1-4. 캐시 디렉터리
`SPD_PI_ENGINE_CACHE` 환경변수 → 없으면 `%LOCALAPPDATA%\SPD Decap PI Evaluator\engine-cache`(QSettings/QStandardPaths 미사용; `APP_DISPLAY_NAME`에 버전이 있어 부적합). 워커가 처음 쓸 때 생성(import 시 파일시스템 무접촉).

### 1-5. 하드웨어 프로파일
`HardwareProfile.detect()` + `plan_sweep(profile, n_ports=len(rails), …)`로 동시 워커 수. 워커 env에만 `OPENBLAS/MKL/OMP_NUM_THREADS = plan.threads`. `plan.notes`는 상태줄로.

### 1-6. validity / numerics_id / 영수증
validity 5줄을 ① `EvaluationView.assumptions`, ② `confidence_note` 끝(GUI가 그리는 곳 `gui/main_window.py:7957-7958`), ③ `evaluation_model_boundary_disclosure`(`_core/services.py:258-290`) 엔진 분기 — ③만으로 `_evaluation_view:4527`이 자동 이어 붙임. 영수증 JSON 원문은 `outputs/engine-receipts/`에 `unique_path`로 보존, 뷰에는 `receipt_sha256`만.

## 2. 기본 동작·재현 테스트

## 3. decap 매핑
`decap_config = {d.refdes: (d.model_id if d.enabled and d.pad_state is not ISOLATION_GAP else None) for d in scenario.decaps if d.current_rail_id.casefold()==rail_id.casefold()} | {d.refdes: None for d in scenario.decaps if source_rail_id==rail_id and current_rail_id!=rail_id}`(`scenario.py:964-1016`). Original은 `original_configuration(rail_id)` 시나리오에 같은 함수. 워커는 한 번 build 후 `set_decaps(config, replace=True)`로 Original/Tuned 연속 solve(P18 GPU build 18 s + 구성당 2 s). 미등록 model_id는 `project.metadata["cap_model_sources"]`의 원문으로 `add_decap_model`. 교차-net 유입은 거부. `DecapBasis`는 구성 N개 분기 자리만 표시(손익분기 42/12; 사인오프 값은 CPU 기저).

## 4. 프로세스 모델
엔진 경로는 **항상 서브프로세스**(cuDSS 핸들 누적, `Model.solve`에 취소 훅 없음, 워커 env 스레드 격리). 기존 `FunctionWorker`(QRunnable, `gui/worker.py:60-102`) 스레드는 그대로 두고 그 안에서 `subprocess.run`(엔진 CLI `sweep`과 같은 구조, `cli.py:186-201`). 새 파일 `_core/solver/engine_worker.py`(약 70줄: prepare → `estimate_cost` 가드 → build → configs 순회 → 영수증; stdout `PROGRESS <pct> <msg>`). 프리즈 빌드: `gui_launcher.py`에 Qt import 전 `--engine-worker` 분기(`gui/app.py:20-21`의 `--smoke-test` 관례). 동시 워커 수 = `plan_sweep(...).jobs`, `ThreadPoolExecutor`. 메모리 가드: `rail.estimate_cost()` → `hardware.rss_per_process_MB/vram_per_process_MB` vs 가용량, 초과 시 `ENGINE_RAIL_TOO_LARGE`.
