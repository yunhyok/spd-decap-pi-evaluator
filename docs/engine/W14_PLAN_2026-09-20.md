# W14 계획 — mesh/solve 경계 분리, 격자 민감도, 수렴 관리자 (2026-09-20 사전 등록)

소유자 승인 2026-09-20("권장안대로 계속 추진"). 근거(소유자): 엔진을 앱과 분리해 두는 이유는 앱 개발이 끝난 뒤에도 워크스테이션 자원으로 추가 검토를 하고 **엔진만 업그레이드**할 수 있게 하기 위함이다. W14는 그 경계를 API로 드러내고, 제품의 fail-closed 수렴 게이트(W11B_REPORT §7-4)가 엔진에도 같은 방식으로 적용될 수 있는지 측정한다.

공통 제약: 물리·수치 변경 없음. 기본 격자(h=200 µm)는 W14 결과와 무관하게 유지하며, 기본값 변경은 별도 소유자 결정이다. `tools/research-claude/`, `docs/handoff/`, `scripts/benchmark_raw_spd_powersi_correlation.py`는 건드리지 않는다. 각 단계는 보고서(`W14A/B/C_REPORT.md`)와 영수증을 남긴다.

## 배경 — 엔진의 mesh는 어디에 있나

엔진의 mesh는 정형 2-D 격자다. `ModelOptions`의 `h`(coarse 200 µm), `fh`(포트 근방 fine 50 µm), `top_h`(최상층 50 µm), `sub=(20,10,10)`(셀당 서브타일; 서브타일 물리 크기 = h/sub_c = 10 µm)가 격자를 정한다. `Model._build`가 래스터화(geometry) → 셀 균질화(homogenise, 서브타일 PCG) → 참조면 탐색(reference) → 소자·노드 맵 → 조립 패턴을 만들고, `Model.solve`가 주파수마다 표면 임피던스를 조립해 LU로 푼다. 균질화는 MFDM 물리의 일부이므로 mesh 단계는 `numerics_id` 안에 남아야 한다. "엔진이 mesh를 만들 필요가 없다"는 계산 코어(solve)에 대해 맞는 말이고, mesh 모듈을 검증 경계 밖으로 빼도 된다는 뜻은 아니다.

## W14-a. API 경계 분리 (수치 불변, 파일 이동 없음)

- `Rail.mesh(options, backend, log) -> MeshedRail`: build 단계만 수행. `MeshedRail`은 `model`(빌드된 `Model`), `options`, 요약(`h, fh, top_h, sub`, 미지수 수, 시트별 셀 수)을 가진다.
- `MeshedRail.solve(freqs, backend=None) -> Result`, `set_decaps`, `decap_basis`, `release_solver`는 `Model`에 위임.
- `Rail.build(options, backend)`는 유지하고 `Rail.mesh(...).model`과 동일 객체 경로를 타게 한다(얇은 래퍼).
- 5개 수치 모듈(geometry, homogenise, reference, model, solver)은 수정하지 않는다 → `numerics_id` 불변. 변경은 `api.py`, README, 테스트에 한정.
- 게이트: (1) `tests/engine`에 Port14(CPU, splu, fast off) `Rail.build().solve` 대 `Rail.mesh().solve` **max |ΔZ| = 0**(비트 동일) 테스트 추가, (2) 기본 스위트 통과, (3) README §2 예제와 새 절 "구조: mesh 단계와 solve 단계"에 경계와 이유(소유자 근거)를 적는다.

## W14-b. 격자 민감도 측정 (사전 등록, 수치 불변)

**대상**: 재현 영수증 9케이스 — 패키지 260729 Port1/7/14/16/18/19 SITE0, 260804 Port18_SITE0, PCB s5m6585 Port1_U1_0/Port50_U1_0. 옵션은 영수증과 동일(`FLAGS_P`, reference `powersi-compatible`, `fh=50, top_h=50, fringe=True`)하고 아래 두 값만 바꾼다.

**변형**: h ∈ {400, 200, 100} µm, `sub_c = h/10`(서브타일 10 µm 고정 → 400: 40, 200: 20, 100: 10). `fh/sub_f`, `top_h/sub_t`, `fine_box`는 고정. 이렇게 하면 coarse 격자 피치만 바뀌고 균질화 래스터 해상도는 같다.

**주파수**: 엔진 사다리 27점(`ladder_freqs`). 백엔드 `auto`(cuDSS+fast, A2000). GPU 실패(메모리) 시 CPU splu로 폴백하고 기록한다. 케이스는 순차 실행(GPU 1개).

**지표**(케이스마다, h=200 기준): Δ_i = 20·log10(|Z_h(f_i)| / |Z_200(f_i)|). (a) 27점 RMS, (b) max |Δ|, (c) f ≥ 100 kHz 구간의 RMS·max, (d) 정보용: 100 kHz Re Z 비 Re Z_h/Re Z_200. 비용: 미지수 N, build 시간, 점당 인수분해 시간, 총 벽시계, 호스트 RSS 최대, VRAM(가능하면).

**판정 규칙(동결)** — 제품 허용치 RMS ≤ 0.2 dB, max ≤ 0.5 dB(evaluator.py `DEFAULT_RMS/MAX_TOLERANCE_DB`)를 27점 전체에 적용:
- R1. 쌍 (200 vs 400)이 9케이스 모두 통과 → W14-c의 기본 검사는 "coarse"(비용 약 +25 %).
- R2. R1 실패, 쌍 (100 vs 200)이 9케이스 모두 통과 → 기본 검사는 "fine".
- R3. 둘 다 실패 → W11-b 면제를 유지하고 관리자는 `convergence_check="none"` 기본으로 넣되, 측정된 민감도를 validity 노트에 적는다. 기본 격자 변경 여부는 소유자 결정.
- 패키지와 PCB는 따로 판정해 어느 설계군이 실패하는지 적는다.

**예측(실행 전 기록, 반증 가능)**: 패키지 (100 vs 200)는 RMS는 0.5 dB 안이지만 max는 고주파(10–100 MHz)에서 0.5 dB를 넘는 케이스가 있을 것(EXP-9: 25 µm trace의 격자 공유 단락, 사이트당 0.8–1.7 mΩ). PCB 2케이스는 두 쌍 모두 통과. (200 vs 400)은 패키지에서 max 0.5 dB 초과 케이스가 다수일 것.

**산출물**: `WORK_DIR/w14b/<case>_h<h>.json`(영수증, light=False), `summary.json`, 그림(케이스별 Δ(f) 스펙트럼, RMS/max 막대), `docs/engine/W14B_REPORT.md`(판정 R1/R2/R3 명시). 스크립트 `tools/engine_studies/w14b_mesh_sensitivity.py`(연구 트리 밖, 엔진 API만 사용).

**해석 한계(미리 적음)**: 이 측정은 자기 일관성(격자 의존)이며 PowerSI 대비 정확도가 아니다. 패키지 R 결손(참조/모델 1.46배)은 격자와 무관한 모델 관례 차이라서 통과 여부와 관계없이 validity 노트는 유지된다.

## W14-c. 수렴 관리자 (W14-b 판정 후 착수)

- `src/spd_pi_engine/convergence.py`: `check_mesh_convergence(rail, options, freqs, pair="coarse"|"fine", backend) -> MeshConvergence{h_pair, rms_db, max_db, converged, cost}`. 순수 오케스트레이션: `Rail.mesh` 두 번 + `solve` 두 번 + 비교. 기준 결과(h=200)는 그대로 반환해 이중 계산이 없게 한다.
- 제품 어댑터: 프로파일 옵션 `convergence_check ∈ {none, coarse, fine}`(기본은 W14-b 판정값). 검사 결과를 제품 형식의 `convergence` dict(`converged`, `frequency_converged`, `modal_converged`, `frequency_rms_delta_db`, `frequency_max_delta_db`)로 채운다. 엔진에는 모달 차수가 없으므로 `modal_converged`는 격자 검사와 같은 값으로 두고 그 사실을 dict와 결과 문구에 적는다.
- `_rejected_comparison_convergence`의 엔진 면제는 `convergence_check != none`인 결과에 대해 제거한다(게이트가 균일 적용). `none`일 때의 면제 유지 여부는 W14-b 판정(R3)과 함께 소유자에게 묻는다.
- 게이트: 제품 테스트 집합 불변(27 FAILED, W11E_REPORT §9), `tests/engine` 통과, 영수증 비트 동일, 기본 프로파일 `layerwise_admittance_v1` 불변.

## W14-b-2. 부록 — 격자 변형의 참조(PowerSI) 대비 (2026-09-20 사전 등록, 분석만, 새 풀이 없음)

동기: W14-b 결과 h=100은 패키지 7케이스 전부에서 3–100 MHz의 |Z|를 h=200보다 1–1.8 dB **높게** 내고, h=400은 h=200과 거의 같다(비단조). 인계 문서는 h=200 모델의 10–100 MHz R이 PowerSI보다 약 25 % 낮다고 기록했다(§6-3). 따라서 "h=100이 고주파에서 참조에 더 가까운가"는 기본 격자 결정에 직접 관련된다.

- **가설 H1**: f ≥ 1 MHz에서 h=100의 참조 대비 오차가 h=200보다 작다(패키지 7케이스 중 ≥ 6, PCB 2케이스 모두). **H0**: 그렇지 않다.
- **지표**: 케이스·사다리 점마다 e_h(f) = 20·log10(|Z_h(f)|/|Z_ref(f)|), Z_ref는 영수증 게이트(`attach_reference`)와 같은 방법으로 사다리 점에 맞춘다. 케이스별 요약: RMS|e_h| (f ≥ 1 MHz)와 RMS|e_h| (f ≤ 1 MHz), h ∈ {400, 200, 100}; |e_100| < |e_200|인 점의 수; G1–G5 게이트 결과(h별).
- **해석 규칙(동결)**: (i) H1 성립 → "고주파 결손의 일부는 격자 미해상"으로 기록하고 기본 격자 변경 여부를 비용(W14-b §6)과 함께 소유자에게 올린다. (ii) h=100이 패키지 ≥ 6/7에서 더 나쁨 → "h=100 이동은 참조에서 멀어지는 이산화 산물, h=200 유지". (iii) 그 외 → 혼재로 기록만. 저주파(≤ 1 MHz)는 h와 무관해야 하며(R 결손 격자 무관, W14-b §3) RMS|e| 차이가 0.1 dB 미만인지 확인한다.
- **산출물**: `tools/engine_studies/w14b2_reference_compare.py`, `docs/engine/figures/w14b2_ref_error.png`, W14B_REPORT.md §10. 파라미터 변경 없음. 판정과 무관하게 h=200 기본값은 이 부록으로 바뀌지 않는다.
