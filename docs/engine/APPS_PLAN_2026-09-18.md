# 엔진 위 앱 시제품 계획 (2026-09-18)

목적: `src/spd_pi_engine` v0.1 API가 소유자가 원래 원한 용도(README §1)에 실제로 쓰이는지 검증한다. 시제품은 `apps/` 아래 스크립트+모듈이며 제품 GUI(`src/spd_decap_pi`)는 건드리지 않는다. 물리·엔진 수치는 바꾸지 않는다. 각 시제품은 (a) 엔진 계약(직접 풀이 대비 ΔZ)으로 결과를 검증하고, (b) 영수증 JSON과 짧은 보고서를 남긴다.

## A1. decap 배치 탐색 (`apps/decap_search/`)
- 입력: SPD, 포트, 목표 임피던스 마스크 |Z(f)| ≤ Z_target(f)(주파수 구간별 상수 또는 표), 후보 decap 사이트 = 레일의 실장 사이트 전체(모델 id 유지), 옵션으로 사이트별 비용 1.
- 방법: `Model.decap_basis(freqs)` 1회 → 후진 제거(backward elimination): 전(全)실장에서 시작해 제거해도 마스크를 만족하는 사이트를 "제거 시 마스크 여유(min over f of Z_target/|Z|)가 가장 큰" 순으로 하나씩 뺀다. 각 단계 비용은 `basis.Z(config)`(구성당 ms~0.1 s). 결과: 마스크를 만족하는 최소 실장 집합과 제거 순서(중요도 순위).
- 검증: 최종 구성과 중간 3개 구성을 `set_decaps`+직접 풀이로 재계산해 ΔZ ≤ 1e-6(GPU) / 1e-9(CPU)(W9 계약). 마스크 판정이 두 경로에서 동일.
- 데모: 260729 Port18(421 사이트), 마스크 = 전(全)실장 |Z|의 1.5배(10 kHz–100 MHz, 사다리 27점 중 저주파 제외한 실용 구간 100 kHz–100 MHz), 실장 최소 개수·소요 시간 보고. PCB s5m6585 Port1(7 사이트)도 한 번.
- 성공 기준: 421 사이트에서 총 탐색 시간 < 10 분(기저 98 s 포함), 검증 통과.

## A2. SITE 간 decap 실장 판단 (`apps/site_decision/`)
- 배경: SITE0/SITE1 포트는 별개 net 사본(W10). 각 SITE는 자기 레일 모델로 계산한다.
- 입력: SPD, SITE 쌍(예: Port18_SITE0 / Port64_SITE1 — `multiport.rail_groups`·포트 헤더로 짝을 찾는 규칙: 같은 net 기본 이름 `…/0`·`…/1`), 판단 대상 사이트 목록(refdes, SITE0 기준; SITE1의 대응 refdes는 위치·net 기준으로 매칭하되 매칭 규칙을 보고서에 적는다), 허용 편차 δ(기본 5 %).
- 방법: SITE마다 `Rail.build` 1회, `set_decaps`로 (전실장, 대상 사이트 미실장) 두 구성 풀이 → 구성별 |Z_SITE0(f)| 대 |Z_SITE1(f)| 편차와, 미실장이 각 SITE에 주는 영향(|Z| 증가율)을 표로. 판단 규칙: "미실장 시 두 SITE의 |Z| 편차가 δ 이내이고 마스크(A1과 동일 형식, 선택)를 만족하면 미실장 가능".
- 검증: 두 SITE 전실장 |Z| 편차가 W10 실측(≤ 0.35 %)과 일치. `set_decaps` 결과는 W8 계약(재빌드 대비 ≤ 1.2e-10)으로 이미 보증.
- 데모: 260729 Port18_SITE0/Port64_SITE1, 대상 사이트 10개(용량 큰 순), δ = 5 %.
